# GitHub 项目评估标准

## 必须检查

对每个候选项目尽量记录：仓库 URL、描述、默认分支、stars、license、最近提交日期、最近 issue/PR 活动、文档入口、安装/运行方式、主要技术栈和项目状态。

## 判断规则

- stars 是采用度的粗略信号，不是质量证明。
- 近期提交和 issue/PR 活动应与项目类型和维护节奏一起判断。
- License 不明确时不得假设可以商用或闭源分发。
- 安装和最小运行验证优先于“看起来很完整”。
- 将候选明确归类为：直接使用、二次开发、技术参考或不建议采用。
- 对关键结论保留 GitHub 链接和核验日期；缺失信息标记为待核实。
